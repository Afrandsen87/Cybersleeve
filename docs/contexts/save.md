# Context: save

Save format, state lifetimes, serialization and versions.

Code: `src/core/save/` (see `docs/contexts/_folders.md`). Text below is moved from the four main docs (updated for S8); headings name the source.

### Wallet and sleeve (S8)
`GameState = { wallet, sleeve }`. The **wallet** is what is shared by every sleeve; the **sleeve** is the one live sleeve (the save keeps sleeves in a map keyed by id with one entry, `main`; in memory there is one `state.sleeve` until a second sleeve exists). Structure only: no behaviour changed, and there is no rule that assigns anything to a sleeve.

| Part | Fields |
|---|---|
| Wallet | `credits`, `inventory`, `runs`, `synths`, `lastLifePurchases`, `automation` (moved unchanged; it resets per life unless a retention skill keeps it), `corporation` (saved as `corporations`, a map keyed by id with one entry), `allTimePeakCredits`, `allTimePeakNetwork` (new statistics: never reset, nothing reads them for gameplay; `notePeaks` raises them) |
| Sleeve | `purchased`, `actions`, `network`, `networkRemainder`, `nodePayoutBonus`, `hackingProficiency`, `heat`, `heatCooldownMs`, `iceRating`, `legend`, `legendCooldownMs`, `moles`, `resleeveLockoutMs`, `peakCredits`, `peakNetwork` (drive the purchase reveal, reset per life), `autoRunOff`, `overclocked`, `focused`, `focusStacks`, `chains`, `bankedCriticals`, `keyToggles` (a keyed collection: `zeroDay`, `adminKey`; absent = off) |

Re-sleeve keeps exactly the positive lists: `CARRIED_OVER_WALLET_FIELDS` (`runs`, `synths`, `corporation`, the two all-time peaks), `CARRIED_OVER_ACTION_FIELDS` (per action `sleeveXp`, `runsTowardSleeveXp`), the buyable currency and effect lists, and the retention skills (`resleeveCarry.ts`). `walletSleeve.test.ts` checks this field by field. Scalars name their owner in `kernel/fields.ts` (`owner: 'wallet' | 'sleeve'`); code that needs a few fields takes `StateSlice<…>`.

## Architecture (from docs/ARCHITECTURE.md)

### State lifetimes
| Field | Re-sleeve | New game |
|---|---|---|
| `corporation` (wallet; the progress of the corporation's actions; it is not the character) | kept | reset |
| `runs` (one record per finished sleeve-run: its own credits per second, action level total and the level of every action), `synths` (each points at a run) and the owned re-sleeve skills (buyables paid in `resleevePoints`, the list `CARRIED_OVER_BUYABLE_CURRENCIES`) | kept | reset |
| `lastLifePurchases` (the action-card purchases the ending life owned, for Reflex Archive; written by `recordLastLife` at every re-sleeve, so it is replaced, not kept) | rewritten | reset |
| `automation` and the automation purchases (Automation core, automation skills), `hackingProficiency`, `iceRating` | only while the matching retention skill is owned (`carryRetention` in `core/resleeve/resleeveCarry.ts`: Daemon Persistence keeps the first, Residual Proficiency a log of the second, Residual Firewall a power of the third) | reset |
| `focusStacks` (Focus slots on an action beyond its first, Overdrive Cap) | reset | reset |
| per action: sleeveXp, runsTowardSleeveXp (the positive list `CARRIED_OVER_ACTION_FIELDS`; nothing else survives; the applied `augments` do not) | kept | reset |
| `allTimePeakCredits` and `allTimePeakNetwork` (wallet statistics: the most ever held; carried by `CARRIED_OVER_WALLET_FIELDS`) | kept | reset |
| `peakCredits` and `peakNetwork` (sleeve; the most held this life; they decide which purchases appear, see `reveal.ts` and `Shop.isRevealed`; `GameEngine` raises them after every slice, sale and start) | reset | reset |
| credits (to `startingCredits`), network, action xp/progress, purchases (all copies), inventory, the Overclock and Focus switches | reset | reset |

### Persistence
`serializeState`/`deserializeState` (versioned JSON, numbers as strings, defensive parsing; only the current format, version 7, is read; any other version is unreadable and backed up). Version 7 is nested: `{ version, wallet: { credits, allTimePeak…, inventory, runs, synths, lastLifePurchases, automation, corporations: { main } }, sleeves: { main: { scalars, purchased, actions, toggles, keyToggles, … } } }`. **Migration** (`save/migrate.ts`, the only place that knows the v6 shape): `migrateSave(text)` turns a flat v6 save into v7 (one `main` sleeve, one `main` corporation, no value changes; the two all-time peaks start at the v6 `peakCredits`/`peakNetwork`; `zeroDaysOn`/`adminKeysOn` become `keyToggles`). `SaveGame` runs it before every read of a stored, remembered or pasted save, so `deserializeState` itself stays current-version only. Tested against two real v6 saves (`testing/fixtures/saves/v6-*.json`, `v7Migration.test.ts`): load, save and flatten equals the file. **Save parts (S8b).** `serialization.ts` only composes; it knows no context's data. Each context that owns saved state implements a `SavePart` (`kernel/savePart.ts`: `write(state)` returns keys for the saved wallet and sleeve, `read(state, raw, config, factory)` restores them defensively): `actions/actionsSave.ts` (`actions`, `autoRunOff`, Overclock/Focus switches, chains), `crits/critsSave.ts` (`bankedCriticals`, `keyToggles`), `items/inventorySave.ts`, `automation/automationSave.ts`, `corporation/corporationSave.ts`, `resleeve/runsSave.ts`, `synth/synthSave.ts`; `save/purchasesSave.ts` (`purchased` + `lastLifePurchases`) stays in `save/` because every other part depends on it. `save/saveParts.ts` lists them in READ order (`SAVE_PARTS`: purchases first, runs before synths, inventory before key toggles, automation last) and declares the WRITE key order (`WALLET_KEY_ORDER`, `SLEEVE_KEY_ORDER`), so the saved text does not depend on read order. Plain-value readers (`isRecord`, `readCount`, `readAmount`, ...) are in `kernel/readValues.ts` so a context can read its part without importing `save/`. To save new state: add a part, put it in `SAVE_PARTS` after what it needs, add its keys to the order lists. Tests: `saveParts.test.ts` (order, keys, defensive reading), `v7Golden.test.ts` (the v7 text of both real fixtures, byte for byte, pinned from the code before the parts existed), `v7Migration.test.ts`.

**Migration safety.** When the stored save is an older version, `SaveGame.load` keeps its text under `cybersleeve.save.premigration` and leaves the main save untouched; the next successful `save()` writes v7 and removes the backup (a failing write keeps it; the Reset button keeps it). A rolled-back (v6) build reads a v7 save as unreadable, copies it to `cybersleeve.save.unreadable` and falls back to `cybersleeve.save.previous` (the v6 text of the last start). **Web Lock:** an old (v6) tab that already holds `cybersleeve.game` makes the new tab report "taken" BEFORE it loads, so a v6 tab cannot overwrite a migrated save while a v7 tab plays, and the reverse; only without Web Locks does the fallback `storage` event apply (the tab that saves first wins; an old tab saving v6 over v7 loses at most the progress since the migration, because the pre-migration text is kept until the first v7 save and the new build migrates a v6 save again). A scalar the save lacks keeps its fresh-game value, so adding a scalar to `fields.ts` needs no new version; changing the meaning of a field does, with a migration. Behind `SaveGame` on an injected `KeyValueStore` (`localStorage` in the browser). Autosave every 10 s, when the page is hidden and on `pagehide`. **One tab plays:** `main.ts` first calls `claimGame(navigator.locks)` (`app/tabGuard.ts`): the first tab takes a named Web Lock and keeps it until it closes; a later tab is told the game is taken and shows a notice BEFORE it loads the save, so the tab that was playing never stops. Without Web Locks the fallback `watchForOtherTab` (`storage` event) stops the tab that sees another tab write the save (there the tab that saves first wins).

Loading is defensive: the inventory keeps only known items and rarities with whole counts above 0 (a save without one loads empty, so no new version was needed; saving leaves used-up stacks out for the same reason, so save, load, save gives the same text), the Overclock and Focus switches keep only known actions that are switched on, a switch only where the action has bought its unlock (Overclock also needs an Overclock effect), Focus only up to the number of slots (base plus bought) (older saves without them load with both off), negative amounts become 0, non-finite times are dropped, the run counter is reduced modulo `runsPerSleeveXp`, copy counts are capped at a safe integer, and a buyable whose `requires` or `parents` are not owned is discarded. Each successfully loaded save is also copied to `cybersleeve.save.previous` (the last known-good save of a session start). A save that exists but cannot be read (corrupt, or from a newer version) is copied to `cybersleeve.save.unreadable` and the game falls back to the previous known-good save, so the next autosave cannot destroy progress. **Export and import** (`SaveGame.exportText` / `importText`, `app/saveTransfer.ts`): the player copies the save as text and can paste one back; a pasted save is validated, stored, and the page reloads (saving is switched off first so the running game cannot overwrite it). The temporary "Reset save" button calls `GameEngine.newGame()` (a full wipe, including sleeve XP) and `SaveGame.clear()` (removes the main and the previous save); it keeps the unreadable-save backup.

## Decisions (from docs/DECISIONS.md)


*Group: Decided 2026-10-25 (by the user, after the second review)*
- Only the current save version is read (nothing has been released). Changing the meaning of a saved field needs a version bump and a migration; adding a scalar does not.

*Group: Decided 2026-10-26 (by the user, after the full review)*
- **Saves:** the last successfully loaded save is kept as `cybersleeve.save.previous` and used when the main save is unreadable; the player can export the save as text and import it (`app/saveTransfer.ts`). Importing stops autosaving and reloads.
