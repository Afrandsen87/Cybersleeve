At a glance

An installable idle game (PWA) in strict TypeScript. Game rules are framework-free and run against injected interfaces; the browser is only a thin shell.

Pure core

core/ has no DOM, timers or storage. Time enters only through GameEngine.tick(deltaMs), so the whole game is deterministic and unit-testable.

Big numbers by interface

All amounts are BigNum. One adapter file wraps break_infinity.js; swapping the library touches nothing else.

Data-driven content

Actions, buyables and tuning are plain data in content/gameConfig.ts. New content is data, not code.

Level rule

Levels start at 1. Defaults: level 2 at 10 XP, then x10 per level, i.e. threshold(level n+1) = firstLevelXp × growthFactor^(n−1). Both numbers are configurable, per track (each action and each action's own sleeve level). A logarithm gives the estimate, which is corrected against exact thresholds, so boundaries are exact and valid far beyond the double range.

Speed & rewards

speed    = f(actionLevel) × f(sleeveLevel) × interfaceSpeed × global.speed
           f = linear: 1 + (L−1)×perLevel   (default: = L)
               exponential: base^(L−1)
duration = baseDuration / speed
per run  = reward × (nodes, if rewardPerNetworkNode) × outputMultiplier × global.reward
           credits are then multiplied by (1 − heat/100), at least 0; network nodes are not taxed
passive  = network nodes × creditsPerNodePerSecond × global.reward × (1 − heat/100)  credits per second
heat     = sleeve.baseHeat, + heatPerRun per completed run, − heatCooldownAmount per heatCooldownMs while heat > 0 (reset by re-sleeve)
           xpPerRun × outputMultiplier × global.xp XP
outputMultiplier = ∏ factor^copiesOwned
sleeve XP (per action): +sleeveXpPerGrant per runsPerSleeveXp runs of that action

Worked example (level worth 0.05 per level): action level 3, sleeve level 2, interface speed 1, base 10 s → 10 s / (1.1 × 1.05) = 8.66 s.

Configuration

Every progression number lives in src/content/gameConfig.ts (typed as GameConfig). Change a value, not code. createGame validates the configuration and refuses to start with a list of problems. The full variable reference is docs/CONFIG.md.
