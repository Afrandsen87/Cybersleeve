### Deploy changelog
`.github/workflows/deploy.yml` runs `scripts/collate-changelog.mjs ${{ github.event.before }}` before the checks, then `biome format` on the result. The script reads `changelog.ts` as it was at the previous push to `main` (`git show`) and the commit subjects since (`git log --no-merges <sha>..HEAD`), and calls the pure `deployChangelog` (`src/build/collateChangelog.ts`):
- If entries were added by hand since then (a `version` label not in the old file), `collateChangelog` replaces them by ONE entry: the newest new label, the changes of all new entries oldest first, exact duplicate lines dropped. The commit subjects are then ignored (hand-written text is curated; mixing both would list a change twice).
- Otherwise `commitLines` turns the commit subjects into changelog lines (oldest first, duplicates dropped; subjects starting `chore:`, `docs:`, `test:`, `refactor:`, `ci:`, `build:`, `wip:`, `internal:` and merge commits are skipped) and they become ONE new entry on top, labelled with the deploy time (UTC, `YYYY-MM-DD HH:MM`, supplied by the script).
- `renderChangelogSource` writes the array back. The commit-subject convention is a standing rule in `CLAUDE.md`. The script only rewrites the CI checkout; the workflow's last step (after the Pages deploy) commits `changelog.ts` back to `main` as `chore: changelog for <sha>` (needs `contents: write`; a `GITHUB_TOKEN` push starts no new run; the `chore:` subject keeps it out of the next entry). Without that commit the next push would start from a file lacking the generated entry and drop it. Consequence: after a deploy `main` is one commit ahead, so pull before the next push. A branch protection rule on `main` would block the bot push (the step fails after the deploy, the site is unaffected). With fewer than two new entries, no baseline (manual run, first push, force push) or an unknown sha, the file is left alone and the step succeeds. If a deploy is cancelled by a newer push, the next run's baseline is that cancelled push, so its entries stay separate. The rewrite is deterministic text merging; an LLM rewrite could be added behind the same function shape but is not built. Needs Node 22.18+ (runs the `.ts` files directly).
