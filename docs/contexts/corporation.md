## Surface and state (S10, current)
- **Keyed by id.** The save keeps the corporation as `wallet.corporations`, a map keyed by corporation id with one entry under `DEFAULT_CORPORATION_ID` (`'main'`, `kernel/savePart.ts`, together with the `CorporationId` and `SleeveId` types). In memory it is still one `wallet.corporation`. `CorporationQueries` / `CorporationCommands` (`engine/apiCorporation.ts`, re-exported by `engine/api.ts`) take an optional `corporationId` on every method; it is ignored while there is one corporation. No assignment rule, no second corporation, no UI.
- **Synthetic sleeves through one question.** `Corporation` takes `Pick<SynthQueries, 'boost'>` (`synth/synthQueries.ts`, implemented by `SynthSleeves`, which calls the shared `synthBoost`). It no longer reads the wallet's `synths` list or the kernel curve itself. Tests: `corporation/corporationKeyed.test.ts`.

## Design (from DESIGN.md)

### 11b. The Corporation

The Corporation is a tab of its own (**Corporation**, shown once the **Incorporation** re-sleeve skill is owned). It is laid out like the Character tab: the **corporation widget** where the Sleeve widget is, the **Holdings**, **Asset Acquisition** and **Hostile Negotiation** widgets in their places (there is no Inventory here), and a grid of **corporation actions** where the character's actions are. The three widgets beside the corporation widget are **empty for now**. The corporation widget lists **Corporate rank** (a plain integer, 1 by default; a naming scheme comes later; it is the corporation's access level and gates its actions), **Owned corporations** (corporations that have been bought; 0, the mechanics come later) and **Employees** (0). Owned corporations and Employees are placeholders shown as constants until the corporation has state of its own; the rank is real.
- **Asset Acquisition** holds the corporation's purchases, paid in credits and **kept through re-sleeving** (like the corporation). The first is the **Corporate access upgrade** (a copy of the character's Access upgrade): **5,000,000 credits** (placeholder), **x100,000 per copy** (5 orders of magnitude), unlimited; each copy gives **+1 Corporate rank**. A corporation action has a required rank (default 1) and cannot be started below it; its card says "Needs corporate rank N". It is meant to be bought after at least two re-sleeves.

- **Corporation actions are not character actions.** They have no interface speed, **action levels** (the same XP rule as the character's, `progression.actionLevels`; each completed run gives the action's `xpPerRun`, default 1; a level speeds the run up exactly like a character action level, `speed.actionLevel`, linear +5% of the base speed per level; no prestige XP bar because the corporation has no reset) but no sleeve levels, no Overclock or Focus, no heat, no reward and no purchases of their own: a run takes the action's own duration sped up by its action level only, because the corporation scales differently from the character. A run is started by clicking the card (there is no auto-run yet), fills its bar and stops when it completes. What a completed run does is a list of **effects**, each one kind of effect with its own parameters (`CorporationEffect`).
- **Purchases of a corporation action** sit in a row on its card, like a character action's, and are paid in credits and kept through re-sleeving. The first is **Stock acquisition** on Insider backstabbing (10,000,000 credits, a placeholder): each completed run then has a **0.5%** chance (half of the upgrade chance) to acquire **one stock of a competitor**. **Stocks owned** is a row of the **Holdings** widget, shown once the purchase is owned or a stock is held. What stocks do is not designed yet.
- **Insider backstabbing** (the first action): a run takes **30 seconds**; each completed run has a **1% chance** (placeholder, in the data) to **upgrade one random Kompromat file** you hold to the next rarity. The file is picked at random among the files held in the rarities that have a next one, so a stack with 9 times the files is picked 9 times as often; files of the highest rarity are never upgraded, and with nothing to upgrade the run does nothing. The total number of files never changes.
- **The corporation survives re-sleeving** (it is not the character): its state is on the carry-over lists, so a run in progress goes on. A new game wipes it.
- **Incorporation** (the root of the Corporation lane of the re-sleeve skills) opens the tab. Like every re-sleeve skill it is kept through re-sleeving. **Synthetic Workers** speeds corporation runs up with the number of synthetic sleeves, and **Synthetic Procurement** opens an (empty for now) Synthetic Sleeves widget for buying new ones.

## Architecture (from docs/ARCHITECTURE.md)

### The Corporation
`Corporation` (`core/corporation/corporation.ts`) starts and advances the corporation's actions (`GameConfig.corporation`, `corporationTypes.ts`); its progress is `GameState.corporation` (`corporationState.ts` creates, writes and reads it; it is on the carry-over list of `state.ts`, so a re-sleeve keeps it). It is a separate unit from `ActionRunner` on purpose: a corporation run takes exactly `baseDurationMs` (no `DerivedStats`, no interface speed, Focus or Overclock) and `GameEngine.advance` ticks it right after the character's actions. A completed run applies its effects through the registry in `corporationEffects.ts` (`CORPORATION_EFFECTS`, typed over every kind, so a new kind needs one entry; `validateConfig` asks the same handlers to check their configuration). `upgradeRandomItem` draws the successes with `binomial` and the stacks they come from with one `multinomial` over the stacks that have a next rarity (the injected `RandomSource`), then moves items with `Inventory.take/add`. `Corporation.durationMs` divides `baseDurationMs` by `levelFactor(speed.actionLevel, level)`; owned `addsCorporationEffect` buyables of an action (`BuyableDefinition.corporationActionId`) apply their effect after the action's own on each completed run (`acquireStock` raises `CorporationState.stocks`, saved and read as 0 when missing). The card shows them (`CorporationActionView.buyables`); the Holdings widget is a stat widget (`CorporationView.holdings`). Corporation actions have action levels (`CorporationLevels` in `core/corporation/corporationLevels.ts`: the XP is `CorporationActionState.xp`, saved as a string and read as 0 when missing; the rule is a `LevelRule` over `progression.actionLevels`; `Corporation.tick` awards `xpPerRun` per completed run; no sleeve levels; a level does not change the run time yet; shown as a level bar on the card). The corporate rank (`Corporation.rank`: `corporation.baseRank` plus the owned `corporateRank` purchases) gates the actions (`requiredRank`); the effect has the `corporate` trait, which keeps its buyable out of the Sleeve widgets and in the Asset Acquisition widget (`isCorporate` in `buyableViews.ts`), and is on `CARRIED_OVER_BUYABLE_EFFECTS`. The corporation is open while a buyable with the `unlocksCorporation` effect is owned (`Corporation.isUnlocked`). In the UI, `ui/view/corporationView.ts` builds `ViewModel.corporation` (the widget rows are placeholder constants until the corporation has state: rank 1, no owned corporations, no employees; the widgets beside it are titled Holdings, Asset Acquisition and Hostile Negotiation and are empty) and `ui/widgets/corporationPanel.ts` draws the tab; the tab itself comes from `tabsView`.

## Configuration (from docs/CONFIG.md)

### `corporation` – the corporation's actions (optional)
| Field | Type | Meaning |
|---|---|---|
| `actions[]` | `{id, name, baseDurationMs, effects[]}` | The actions of the Corporation tab, in order. `id` must be unique; `baseDurationMs` (> 0) is the run time at level 0: **only the action level speeds a corporation action up** (`speed.actionLevel`, as for a character action; no interface speed, sleeve level, Focus or Overclock). `xpPerRun` (optional, > 0, default 1) is the action XP each completed run gives; the action levels follow `progression.actionLevels` (there are no sleeve levels, and a level changes nothing yet). `effects[]` are applied once for each completed run, in order |
| effect `{kind: 'upgradeRandomItem', itemId, chance}` | `itemId` an item that has rarities, `chance` in (0, 1] | Each completed run has `chance` to upgrade ONE random stack-member of the item one rarity up: the stack is drawn weighted by how many are held, the highest rarity is never upgraded, nothing held does nothing. Real content: Insider backstabbing, `kompromat`, 0.01 (placeholder) |

`baseRank` (optional integer >= 1, default 1) is the corporate rank before any `corporateRank` purchase; an action's optional `requiredRank` (integer >= 1, default 1) is the rank needed to start it. The buyable effect `{kind: 'corporateRank', amount}` (integer >= 1 per copy) adds to the rank; such a buyable is listed in the Asset Acquisition widget and kept through re-sleeving (`content/buyables/corporation.ts`).

A buyable with `corporationActionId` is shown on that corporation action's card (not in Asset Acquisition); the effect `{kind: 'addsCorporationEffect', effect}` adds a corporation effect (e.g. `{kind: 'acquireStock', chance}`, chance in (0, 1]) to every completed run of that action while owned. Such buyables are kept through re-sleeving (`content/buyables/corporation.ts`).

The tab is opened by a buyable with the effect `{kind: 'unlocksCorporation'}` (real content: the re-sleeve skill Incorporation). Leave `corporation` out for a game without a Corporation tab. A new kind of effect is one union member in `core/corporation/corporationTypes.ts` plus one entry in `core/corporation/corporationEffects.ts`.

## Decisions (from docs/DECISIONS.md)


*Group: Decided 2026-10-27 (by the user, Corporation and item tuning)*
- **Corporation tab.** A tab of its own, laid out like the Character tab: the corporation widget in place of the Sleeve, the Network, Sleeve Improvements, Network Exploitation and Inventory widgets in their places but EMPTY, and a grid of corporation actions in place of the character's. It is opened by the **Incorporation** re-sleeve skill (effect `unlocksCorporation`, tip "opens the Corporation tab"; it was a placeholder before). What the corporation widget will show is not decided: it stays empty.

*Group: Decided 2026-10-27 (by the user, Corporation and item tuning)*
- **Corporation actions are not character actions** (`GameConfig.corporation`, `core/corporation*.ts`): no interface speed, levels, Overclock, Focus, heat, reward or purchases; a run takes exactly `baseDurationMs` ("they are in the corporation, which scales differently"); a manual start, no auto-run yet. A completed run applies **effects** (`CorporationEffect`; one registry entry per kind in `corporationEffects.ts`). **The corporation survives re-sleeving** (`state.ts`, it is not the character); a new game wipes it. Saved as `corporation`; no save version bump (a save without it loads idle).

*Group: Decided 2026-10-27 (by the user, Corporation and item tuning)*
- **Insider backstabbing** (the first action): 30 s; each completed run has a 1% chance (placeholder, data) to upgrade ONE random Kompromat file to the next rarity. Reading chosen with the user: the stack is picked weighted by how many files each holds; the top rarity is never upgraded; nothing to upgrade does nothing. A batch draws its upgrades with `binomial` and the stacks with one `multinomial` (an item upgraded inside a batch is not picked again in the same batch).
